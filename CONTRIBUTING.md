# Contributing to MAIPL

Thank you for helping improve MAIPL.

## Before opening a change

- Use an issue to discuss substantial features or architectural changes.
- Do not include credentials, private datasets, personal information, or
  production infrastructure details.
- Keep changes focused and include tests or documentation where appropriate.

## Development workflow

1. Fork the repository and create a branch from `main`.
2. Follow the setup instructions in the component README.
3. Run the relevant tests, linters, and builds locally.
4. Open a pull request describing the motivation, implementation, and
   verification performed.

By submitting a contribution, you agree that it is licensed under the GNU
General Public License version 3 and that you have the right to submit it.

## Security issues

Do not open public issues for vulnerabilities. Follow [SECURITY.md](SECURITY.md).
